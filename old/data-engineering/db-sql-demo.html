Interactive SQL Lab • Watch Queries Run

SQL Demo: See Every Clause in Action

A SQL query is a list of steps applied to rows. In this lab you pick options, read the SQL they build, press Run and watch each step happen: WHERE checks rows, JOIN pairs them, GROUP BY puts them in buckets, ORDER BY sorts them and HAVING filters the buckets.

How to use this lab

Each section has its own controls. Run plays the animation, Reset puts the data back. Changing an option resets that section.

Foreign Keys: Rows That Point at Other Rows

          Step 3 • Filtering Rows
          
WHERE: Keep Only the Rows You Want

          

            WHERE tests every row against a condition. Rows where the condition is TRUE are kept; rows where it is FALSE (or NULL) are thrown away. Pick a ready-made filter or build your own, then press Run.

          Step 4 • Combining Tables
          
JOIN: Match Rows Across Two Tables

          

            A JOIN pairs each row of one table with the rows of another table that share a value, here cust_id. The join type decides what happens to rows that find no partner.

          Step 6 • Sorting
          
ORDER BY: Sort the Result

          

            A table has no built-in order. If the order matters, you must ask for it with ORDER BY.           Step 7 • Filtering Groups
          
HAVING: Filter the Buckets

          

            WHERE filters rows before grouping. HAVING filters groups after grouping, so it can test aggregates like COUNT(*) or AVG(salary). Turn on the WHERE option to see both work in one query.

          Putting It Together
          
The Order SQL Really Runs In

          

            You write SELECT first, but the database runs it fifth. Knowing the real order explains most beginner errors, such as why WHERE cannot use COUNT(*) but ORDER BY can use a column alias.
