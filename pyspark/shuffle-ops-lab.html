Shuffle Operations Lab

Choose where the data comes from (object-store files, an RDBMS over JDBC, an MPP warehouse), what the DataFrame does (from a plain select to joins, windows and a full multi-shuffle pipeline), where it lands, and how big it is. The lab rebuilds the physical plan, stages, exchanges, partition sizes, spill, task timeline and tuning advice on every change.

The cost model is illustrative: it uses real Spark rules (maxPartitionBytes/openCostInBytes split sizing, hash/range partitioning, partial aggregation, AQE coalesce and skew-join thresholds, broadcast thresholds) with simplified throughput numbers. Use it to reason about shape and direction — then confirm on your cluster in the Spark UI.

              6. Narrow vs Wide: When Does a Shuffle Happen?
            

            Operation ladder from simple select to complex pipelines — click "Load" to simulate any row
          

        

        

          

            
Narrow — each output partition depends on one input partition

            
            
select · filter · withColumn · map · union · coalesce — pipelined in one stage, no data movement.

          

          

            
Wide — each output partition reads from every input partition

            
            
groupBy · distinct · join (non-broadcast) · orderBy · window · repartition — stage boundary, disk + network.
