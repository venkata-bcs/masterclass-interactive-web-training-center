Section 3 • Relational Database Scale-Out Ingestion

Reading & Writing RDBMS via Parallel Partitioned JDBC

Never do a single-threaded JDBC read again. Learn how PySpark distributes parallel JDBC connections across Oracle, PostgreSQL, MySQL, and Microsoft SQL Server to extract 100M+ rows in minutes.

The Single-Threaded JDBC Bottleneck vs. The Partitioned Solution

The #1 beginner mistake in PySpark
THE TRAP

Basic spark.read.jdbc()

When you call spark.read.jdbc(url, table, properties) without partitioning parameters:

  • Spark sends ONE single SQL query (SELECT * FROM table).
  • Exactly 1 Executor Task is scheduled. All other 50+ cores in your cluster sit 100% idle!
  • The single executor driver process buffers all rows, often leading to java.lang.OutOfMemoryError.
THE SOLUTION

Parallel Partitioned Read

By providing partitionColumn, lowerBound, upperBound, and numPartitions:

  • Spark calculates partition strides and generates N independent parallel SQL queries.
  • N tasks run concurrently across all worker executors in the cluster.
  • Each executor fetches its partition stream in parallel directly into memory partitions.
