Understanding AI

Understanding AI

Four waves of making computers useful. Each one builds on the one before.

Wave 1

Automation: rules you write

  • A person writes exact steps: if this happens, do that.
  • Fast, cheap and predictable for repeat work.
  • Examples: scheduled reports, invoice emails, RPA bots, form workflows.
  • Limit: it cannot handle anything the rules did not expect.
Triggernew order
Ruleif paid
Actionsend invoice
Wave 2

AI / ML: patterns learned from data

  • Instead of writing rules, you show the computer many examples.
  • Training finds the pattern; the result is a model.
  • The model predicts for new data: price, risk, demand, spam or not.
  • Examples: fraud scores, product recommendations, sales forecasts.
Wave 3

Gen AI: new content from a prompt

  • A large language model (LLM) learned from huge amounts of text, code and images.
  • You describe what you want in plain words: the prompt.
  • It generates text, code, summaries, images, answers.
  • Limit: it only talks. It cannot act in your systems by itself.
> Write a polite delay notice for order #4512
Hi Priya, your order #4512 is running two days late. We're sorry, and we've added free express shipping.
Wave 4

Agentic Development: AI that gets work done

Give the AI a goal instead of a single question. It plans, uses tools, checks results and keeps going until the job is done.

Agentic • 1

Agents: an LLM with tools

  • Instructions: who it is and what it may do.
  • Tools: functions it can call: search, database, email, code.
  • Memory: what happened so far, and facts to remember.
  • Guardrails: limits, approvals and checks.

Agentic • 2

Agentic Loops: think, act, observe, repeat

  • Think: the model decides the next step.
  • Act: it calls a tool.
  • Observe: it reads the tool's result.
  • Decide: done? Answer. Not done? Loop again, up to a safe limit.

Agentic • 3

Agent Swarms: a team of specialists

  • A lead agent splits a big job into parts.
  • Specialist agents work in parallel, each with its own tools and context.
  • Results flow back; the lead checks and combines them.
  • Used for research, large code changes and complex workflows.

Term 1

LLM: Large Language Model

  • A model trained on huge amounts of text and code.
  • It works by predicting the next token again and again.
  • Examples: Claude, Gemini, GPT, Llama.
The capital of India is ___

Illustrative probabilities for the next token.

Term 2

Harness: the code around the model

  • The LLM only reads and writes text. The harness does everything else.
  • It runs the loop, calls tools, keeps memory, applies guardrails.
  • Examples: Claude Agent SDK, LangGraph, CrewAI, Google ADK.

Term 3

Tokens: how models read text

  • Text is split into small pieces called tokens: words, parts of words, punctuation.
  • Models have a context window: the most tokens they can read at once.
  • You pay per token, for both input and output.

Term 4

Data / State: what the agent knows right now

  • The model itself forgets everything between calls.
  • The app sends the conversation so far every time, and keeps a state object for the task.
context used
Where is order 4512?
tool: get_order(4512) → "shipped"
It shipped today and arrives Friday.
state = { order: 4512, status: "shipped", step: 3 }
Term 5

MCP: Model Context Protocol

An open standard that plugs AI apps into tools and data. Write a connector once as an MCP server, and any MCP-ready AI app can use it.

Term 6

RAG: Retrieval-Augmented Generation

Before answering, look up the right facts from your documents and give them to the model, so it answers from them instead of guessing.

Term 7

Observability: see inside every run

  • Traces show each step of a run and how long it took.
  • Logs keep prompts, tool calls and errors.
  • Metrics track cost, tokens, latency and quality.
  • Tools: OpenTelemetry, LangSmith, Langfuse, Grafana.

MLOps: running AI in production

  • DevOps for models: version data, prompts and models.
  • Evaluate before every release; deploy safely.
  • Monitor drift and quality, then improve. Also called LLMOps for LLM apps.

Git & GitHub Actions

  • Git saves every change to your code, prompts and configs, so you can review and undo.
  • Work in branches and merge through pull requests on GitHub.
  • GitHub Actions runs your tests and evals on every push, then deploys.
# .github/workflows/tests.yml
name: tests
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install -r requirements.txt
      - run: pytest

Foundation • 4

Docker

  • Packs your app and everything it needs into one image.
  • The same container runs on your laptop, in CI and in the cloud.
  • Docker Compose runs the app with its database and vector store together.
# Dockerfile for a FastAPI agent service
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
Agent framework • 1

CrewAI

  • Build a crew of role-based agents that work through tasks together.
  • Each agent has a role, goal and backstory; tasks have expected outputs.
  • Flows add event-driven control for production pipelines.
from crewai import Agent, Task, Crew

writer = Agent(role="Writer", goal="Explain AI simply",
               backstory="Friendly tech teacher")
task = Task(description="Explain RAG",
            expected_output="3 short bullet points",
            agent=writer)
print(Crew(agents=[writer], tasks=[task]).kickoff())

Agent framework • 2

LangGraph

  • Build agents as graphs: nodes do work, edges decide what runs next.
  • Shared, typed state; checkpoints let runs pause and resume.
  • Great for loops, branching and human approval steps.
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    question: str
    answer: str

def reply(state: State):
    return {"answer": "You asked: " + state["question"]}

g = StateGraph(State)
g.add_node("reply", reply)
g.add_edge(START, "reply")
g.add_edge("reply", END)
print(g.compile().invoke({"question": "What is RAG?"}))

Agent framework • 3

Claude SDK

  • The Anthropic SDK calls Claude models: messages, tools, streaming, caching.
  • The Claude Agent SDK gives you the Claude Code agent harness as a library.
  • Plus MCP support and Managed Agents for hosted agents.
import anthropic

client = anthropic.Anthropic()   # reads ANTHROPIC_API_KEY
msg = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user",
               "content": "Explain RAG in one line"}],
)
print(msg.content[0].text)

Agent framework • 4

Google ADK

  • Google's open-source Agent Development Kit for building agents in code.
  • Plain Python functions become tools; agents can be composed into teams.
  • Built for Gemini, with a local dev UI and deployment to Google Cloud.
from google.adk.agents import Agent

def get_weather(city: str) -> dict:
    """Return the weather for a city."""
    return {"city": city, "forecast": "sunny"}

root_agent = Agent(
    name="weather_agent",
    model="gemini-2.5-flash",
    instruction="Answer weather questions with the tool.",
    tools=[get_weather],
)

Data & MLOps • 1

Vector Databases

  • Store text as embeddings: lists of numbers that capture meaning.
  • Similarity search finds the passages closest to a question: the R in RAG.
  • Start with pgvector in PostgreSQL; managed options scale further.
-- pgvector: vectors inside PostgreSQL
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE docs (
  id serial PRIMARY KEY,
  body text,
  embedding vector(1536)
);
-- 5 passages closest to the question's embedding
SELECT body FROM docs
ORDER BY embedding <=> $1  -- cosine distance
LIMIT 5;

Data & MLOps • 2

MLflow

  • Open-source platform to track experiments: parameters, metrics and results of every run.
  • Model registry versions models and promotes them from staging to production.
  • Also traces and evaluates LLM and agent apps.
import mlflow

mlflow.set_experiment("refund-classifier")

with mlflow.start_run():
    mlflow.log_param("model", "logistic_regression")
    mlflow.log_param("max_iter", 200)
    mlflow.log_metric("accuracy", 0.94)
# compare every run side by side in the MLflow UI
