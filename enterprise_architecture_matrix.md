# Enterprise AI Architecture Matrix

This matrix maps the core operational roadmap, asset file structures (`skills.md`, `memory.md`, `tools.md`), and LLM training strategies against your target platforms: **Strands AI**, **AWS Bedrock**, **Azure AI Foundry**, **LangGraph**, and **CrewAI**.

| Core Architectural Layer | Strands AI | AWS Bedrock | Azure AI Foundry | LangGraph | CrewAI |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. Harness & Sandbox** | Managed, low-code secure agent runtimes for enterprise workflows. | **Bedrock Agent Runtime** with managed execution environments. | **Azure AI Agent Service** (integrated with Azure Container Apps/Sandboxes). | Custom-defined runtimes; typically hosted in **LangGraph Cloud** or custom Docker images. | Python-based task execution wrappers; requires external sandboxing (e.g., Docker). |
| **2. State & Data** | Built-in enterprise data isolation and transaction memory layers. | Session persistence via **Bedrock Knowledge Bases** and built-in session state APIs. | **Cosmos DB** integration natively managed through AI Foundry connections. | **LangGraph Persistence (Checkpointers)** via Postgres, Redis, or memory for time-travel. | Built-in memory systems (Short-term, Long-term, Entity) backed by local storage or Mem0. |
| **3. Function Calling** | Visual tool-binding and pre-integrated enterprise system APIs. | **Bedrock Action Groups** mapping LLMs to AWS Lambda schemas. | Natively integrated **Azure Functions** and OpenAPI plugin definitions. | Granular control via **LangChain tools** wrapped inside explicit state graph nodes. | Declarative **CrewAI Tools** class with automatic Pydantic argument validation. |
| **4. Edge Deployment** | Focuses on cloud-to-hybrid workflows rather than pure local edge. | Limited native edge; routes via **AWS IoT Greengrass** or local hardware running optimized models. | **ONNX Runtime** compilation and deployment to Azure IoT Edge. | Code-first Python structure deployable anywhere (local edge server, mini-PC). | Local Python execution; easily embedded in edge apps running local Ollama/Llama.cpp. |
| **5. Start & Stop** | Managed operational dashboard with visual pause/resume gates. | Session-based lifecycle tokens managed via runtime API endpoints. | Managed enterprise orchestration pipelines with cloud-native lifecycle states. | Graph-level **breakpoints** that interrupt compilation before/after specific nodes. | Sequential or hierarchical process controls with manual override flags. |
| **6. Testing & Eval** | Visual testing playgrounds and scenario simulation runs. | **Bedrock Model Evaluation** (automatic or human-led evaluation jobs). | **Azure AI Evaluation SDK** using built-in metrics (groundedness, safety). | **LangSmith** ecosystem for unit testing, dataset tracking, and backtesting. | Simulation mode (`crew.kickoff(inputs={})`) with verbose debugging outputs. |
| **7. Auditing & Tracing** | Enterprise-grade audit trails for actions and security posture. | **AWS CloudWatch Logs** and **AWS S3** delivery for raw prompt/response pairs. | **Azure Monitor** and Application Insights via OpenTelemetry standards. | **LangSmith** for granular, tree-structured trace views of every single node execution. | Native integrations with **Agentops**, **LangShare**, or standard stdout tracing logs. |
| **8. Orchestration** | Visual multi-agent workflow builder focused on business processes. | **Bedrock Agents** orchestrating sequential reasoning steps natively. | **Azure AI Agent Service** orchestration engines and prompt flow routing. | **Stateful multi-agent graphs** using explicit channels, reducers, and conditional edges. | **Role-based multi-agent crews** using sequential, hierarchical, or consensual processes. |
| **9. Guardrails** | Inherent corporate security policies and data governance gates. | **Guardrails for Amazon Bedrock** (PII masking, toxic filters, denied topics). | **Azure AI Content Safety** (harm filters, jailbreak detection, prompt shields). | Programmatic guardrail nodes (e.g., placing a LlamaGuard node before tool calls). | Task-level input/output validation hooks and custom guardrail logic in python. |
| **10. RAG Pipeline** | Pre-built enterprise connectors to common knowledge silos. | Managed **Knowledge Bases for Amazon Bedrock** (chunking, vectorizing, OpenSearch). | **Azure AI Search** integrated directly with chunking and indexing pipelines. | Custom-built RAG logic inside graph nodes allowing advanced rerankers/loops. | Built-in RAG tools (PDF, Web, RAG vector integrations) assignable to specific agents. |
| **11. MCP Integration** | Adaptable to enterprise API integrations via REST/GraphQL hooks. | Implemented via custom Lambda action groups translating to MCP protocols. | Managed plugin architecture compatible with standard enterprise API specs. | Direct implementation via Python-based **MCP clients** inside tool nodes. | Custom tools can be written to act as bridges to local or remote MCP servers. |
| **12. MLOps / LLMOps** | High-level dashboard tracking agent operational efficiency. | **Amazon SageMaker** integration for model fine-tuning and deployment tracking. | Unified lifecycle management from prompt engineering to **Azure ML registries**. | Deeply tethered to **LangSmith** for prompt versioning and deployment automation. | Focuses on prompt engineering layer; tracks agent performance via telemetry hooks. |
| **13. HITL (Human-in-Loop)** | Built-in business user approval steps and intervention UIs. | **Amazon Augmented AI (A2I)** or custom UI integrations via API pause cycles. | **Azure AI Prompt Flow** human intervention and routing components. | Native **human-in-the-loop state interrupts** requiring manual input to resume graph. | `human_in_the_loop=True` parameter triggers terminal/UI prompts for task approval. |
| **14. `skills.md` Implementation** | UI-driven drag-and-drop capability mapping. | Handled via API-mapped **Action Group manifest definitions**. | Handled via **Azure AI Agent Plugin Schemas** and App Registration bounds. | Explicit **LangChain Runnable** primitives defined programmatically inside nodes. | Assigned directly via agent configuration objects using the **`skills` attribute**. |
| **15. `memory.md` Implementation** | Native tenant-isolated storage buckets. | Session attributes dynamically passed via **DynamoDB/S3 integration vectors**. | **Cosmos DB/Azure SQL** backend storage mapping persistent entity frames. | Graph-managed state channels mapped to permanent **Postgres/Redis Checkpointers**. | Declarative **Mem0 framework integrations** storing entity, context, and short-term arrays. |
| **16. `tools.md` Implementation** | Centralized visual enterprise API catalog connectors. | JSON-based **OpenAPI schemas** declared directly inside Lambda function hooks. | Unified **OpenAPI/Swagger manifest endpoints** mapped through AI Studio connections. | Standard **Pydantic schema definitions** bound to programmatic `@tool` decorators. | Custom wrappers inheriting from the **`BaseTool` class** with type validation gates. |
| **17. LLM Training / Tuning Strategy** | Out-of-the-box system prompt templates optimized for Strands engines. | Custom SFT/Fine-tuning jobs run via **Bedrock Custom Models** with synthetic tool datasets. | Fine-tuning via **Azure AI Studio UI or SDK** using structured JSONL evaluation datasets. | Focuses on systemic prompt engineering, SFT optimization, and **LangSmith trajectory evaluations**. | Prompt optimization through explicit **Few-Shot training examples** loaded directly into agents. |
